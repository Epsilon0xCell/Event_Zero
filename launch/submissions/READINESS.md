# Submission Readiness: What Must Be True Before Each Send

Status: DRAFTS ONLY. Nothing in this folder has been posted, submitted, opened as a PR, or sent as modmail.
Prepared: 2026-11-23.

Each submission fires on the founder's word, one at a time, in the order listed. A condition that cannot be verified is treated as not met.

## Gate for all three submissions

1. **The next GitHub push has landed.** The pushed tree contains the current README.md including the Global Defence Initiative section, the demo video under demo/, and the example reports the drafts quote. Verified by reading the repo at its new head and matching the verdict headlines in examples/fake_malware.verdict.txt and examples/clean_crack.verdict.txt against the drafts.
2. **Actions status is known and honestly describable.** Either the tests and verify workflows are green on the pushed head, or, if Actions is still not running, every draft statement that touches verification stays in its current local terms (tests and corpus results are described as project-run, never as CI-verified). The README badges resolve to real workflow states, not to a "no status" placeholder that a listing tester would read as broken.
3. **OPSEC blockers are done.** The doxxing scrub decision items for the GitHub account have been decided and the decided fixes executed, per the public ghost identity cleanup work. Advertising draws exactly the attention the scrub exists to precede, so no submission goes out before this gate clears.
4. **Dates and checks inside the drafts are refreshed.** The FMHY issue draft's "checked on" line and the PR draft's date are updated to the real submission week, and the not-already-listed check is re-run on FMHY's Single Page that week.

## Submission 1: FMHY (fmhy-submission.md)

Ready when, in addition to the gate above:

- The founder has chosen the route: issue first (recommended by FMHY's own guide), with the PR draft held as the fallback if staff ask for one.
- A session in the FMHY Discord link testing process is the accepted next step after the issue. Their Discord opens every Friday; whoever submits is prepared to join, post the tool for testing, and answer testers.
- Known gaps are accepted as stated in fmhy-submission.md section 6: no packaged release or download yet, CC BY-NC 4.0 licence rather than an OSI licence, Discord testing not yet done. If the founder wants the release gap closed first, a tagged GitHub Release with built GUI downloads becomes a pre-submission task and this note gets updated.

Fire word: "send FMHY".

## Submission 3: r/piracy post approval modmail (rpiracy-post-modmail.md)

Ready when, in addition to the gate above:

- The wiki modmail has been sent and answered, or the founder explicitly decides to ask for the post first. Default order is wiki first, post second.
- The demo video is in the pushed tree at demo/event-zero-demo.mp4 and plays from the GitHub repo page.
- The post itself is drafted only after the mods answer, and follows any conditions they set (title, flair, weekly thread, no video) exactly.

Fire word: "send post ask".

## After any send

- Record the date, the exact text sent, and where, in this folder.
- One ask, then wait. No follow-up message before the other side replies or a full week passes, whichever the founder decides at send time.
- Any conditions imposed by FMHY staff or r/piracy mods are completed and verified before the next submission in the order fires.
