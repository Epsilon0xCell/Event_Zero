File note 01

What I built, in my own words

I built Event Zero because I wanted a straight answer about a suspicious file without handing that file to a website and without running it. I point the tool at a path, and it reads the bytes and tells me what it can prove from those bytes alone: hashes, format, entropy, strings, and the indicators hiding in those strings.

Local mode is the part I trust for a first look. It is pure Python standard library, it works offline, it needs nothing installed beyond Python 3.8 or newer, and it never executes the sample. It writes a plain summary to the terminal and a JSON report beside it, and that report states its own limits in writing.

Autonomous mode is the longer route. It builds a BlackArch container, copies the sample in, and lets Gemini direct standard analysis tools over several rounds until the model marks the work complete or the iteration cap is reached. I keep both modes in one file so the command line, the exit codes, and the report shape stay in one place.

fake_malware is the specimen I return to. I made it as the test sample for this analyzer, with planted strings I can check the findings against. This page is its dossier: what local mode found, the sheets I drew to explain the system, and an honest note on where the tool stops.

A short piece of the engine, as written

    @staticmethod
    def _shannon_entropy(data: bytes) -> float:
        if not data:
            return 0.0
        # I count bytes in a plain Python loop. That is slow on a large
        # file, and I keep it because local mode promises standard
        # library only and the files I analyse are small enough that
        # the simple version wins.
        counts = [0] * 256
        for b in data:
            counts[b] += 1
        entropy = 0.0
        for c in counts:
            if c:
                p = c / len(data)
                entropy -= p * math.log2(p)
        return entropy

Section C

Local and autonomous, side by side

Local mode

I reach for local mode first. I run it on my own machine, offline, and it reads the sample as bytes from start to finish. It computes hashes, parses Mach-O, ELF, and PE headers, measures entropy, extracts ASCII and UTF-16LE strings, and pulls URLs, addresses, and keyword hits from those strings.

It needs no Docker, no network, and no key. When it finishes, it leaves a JSON report next to where I ran it, or at the path I give it. If the file is missing, it fails cleanly and tells me why.

Autonomous mode

I use autonomous mode when I want the longer examination. It builds or reuses a BlackArch image, starts a container with the sample inside at a fixed path, and loops: Gemini proposes analysis code, that code runs in the container, and the results go back for the next round.

It needs Docker running and a Gemini key. If the calls fail again and again, a built in fallback does basic static work inside the container instead. At the end it writes a timestamped report, then stops and removes the container and keeps the image for reuse.

Section E

Where it stands, honestly

Local mode is the finished half of this tool in the way that matters to me: it runs anywhere Python runs, it states its limits inside its own report, and I can verify every number it prints by hand. Static analysis only is a real limit, and I would rather print that limit than dress a lead up as a verdict.

Autonomous mode works, but its container path is still verified by hand more than by test. If I return to this repo, that is the gap I would close first: a container run in the test suite, so that half stops resting on my own runs alone.

For a genuinely hostile file, my README says it and I will say it here too: use a hardened, network isolated virtual machine rather than a workstation. Neither mode in this tool replaces a real sandbox, and neither mode should be read as a final word on a file.

Disclosure on the specimen

fake_malware is a real Mach-O 64-bit ARM64 executable, not inert text. If executed, its embedded steps write whoami, id, and uname output to files under /tmp, create /tmp/persistence.sh and make it executable (written, not installed in any autostart location), dump a process list to /tmp, remove a test file, and attempt a connection to 127.0.0.1:4444.

Its printed simulation list includes a crypto mining simulation line, with no mining pool endpoint in the binary. Local mode never executes it: local mode reads it as bytes and analyzes it, and autonomous mode runs analysis tooling on it inside a container.

I treat this file as live sample code. I do not execute it outside a controlled analysis environment, and I ask anyone who clones the repo to do the same.
