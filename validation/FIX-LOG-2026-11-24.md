# Fix Log, 2026-11-24: Accuracy Audit Defects

Every PROVEN defect in `validation/ACCURACY-AUDIT.md` that the fix task
enumerated is fixed in the working tree, each paired with a regression
test in `tests/test_accuracy_audit_fixes.py` derived from the audit's
own probe. Direction throughout is fail-closed only: no existing
blocker was weakened to make a test pass. Nothing is committed or
pushed; all changes are in the working tree. `validation/campaign/`
was not touched.

Numbering below is the fix task's (1 to 16); the audit's own defect
number is given where it differs. Probe results are from the rebuilt
audit probe suite, run before the fixes and again after.

Final full-suite result: **191 passed** (167 baseline tests plus 24
new regression tests), run with
`~/ezpush-venv/bin/python -m pytest tests/ -q`.

One existing test was updated because it encoded a proven defect:
`tests/test_verdict.py::test_no_single_cracked_binary` asserted NO
ACCOUNTED for a lone binary on patch evidence alone, which is audit
defect 1. It now asserts YES UNACCOUNTED and keeps its assertion that
patch evidence is still collected as annotation. The update is
documented in the test itself.

## 1. Patch-evidence NO path (audit defect 1, P0)

Fix: `event_zero/verdict.py`. The `elif patch_ev:` branch that granted
NO ACCOUNTED to a lone compiled binary was deleted. A compiled binary
with no reference and no digest-verified signature now always falls to
the UNACCOUNTED branch; when patch-like signals exist, the message
says they are annotation, not an accounting (a NOP run is also
ordinary alignment padding, and a license string appears in every
licensed program). `find_patch_evidence` is unchanged as a collector;
its docstring now states the annotation-only rule.

Regression tests: `test_defect1_lone_binary_patch_signals_never_no`,
`test_defect1_gcc_hello_never_no`.

Probe: before, the GCC hello binary carrying a "license check
routine" string earned `NO: NO MALWARE / ACCOUNTED`. After:
`YES: MALWARE FOUND / UNACCOUNTED`, file verdict `YES: UNACCOUNTED`.

## 2. Report string cap of 2,000 (audit defect 2, P0)

Fix: `event_zero/analyzer.py`. The report's judgement string list
`"all"` is no longer sliced to 2,000 entries; judgement layers read
the full string set. Display surfaces already cap where they render.

Regression test: `test_defect2_wallet_position_does_not_change_verdict`
(asserts the analyzed string count exceeds 2,000 and that the
late-wallet and early-wallet miner scripts give the identical PROVEN
verdict).

Probe: before, both probe files printed PROVEN, but through a wrong
path (numbered filler tripped the old bare-"1688" KMS baseline, see
defect 6), while the analyzer silently discarded every string past
2,000, which is the position dependence the audit proved with its own
pair. After: strings are uncapped, the baseline no longer fires on
filler digits, and both files are PROVEN through the real miner chain.

## 3. Script caps: 20,000-char source and the ledger window (audit defect 3, P0)

Fix: `event_zero/analyzer.py` (`script_analysis` keeps the full
decoded source and records `source_chars`), and the report now
carries `script_source_full`. `event_zero/families.py` (`_blob`,
`_scripts`) and `event_zero/verdict.py` (`malicious_chains`,
`tampering_findings`, `kms_baseline`) all consume the full source
instead of the 4,000-char display excerpt, so the per-line ledger
runs over every line of the file. Where decoding itself fails, the
analyzer records an explicit truncation marker (see defect 15).

Regression test: `test_defect3_long_script_fully_ledgered` (asserts
the ledger's line count equals the full source line count for a
23,143-char script and that the crontab tail past char 20,000 is
flagged).

Probe: before, the headline was PROVEN via the uncapped string layer
while the ledger itself had never seen the tail (the audit calls this
defect only partially probe-proven for exactly that reason). After:
PROVEN, with the ledger covering all lines and the tail flagged.

## 4. Ledger gate applies to all scripts (audit defect 4, P0)

Fix: `event_zero/verdict.py`. The script-ledger blocker previously
fired only when the claimed function was "activator". It now fires
for every file the engine identifies as a script (a real script
language from a code extension or shebang): any ledger-unaccounted
line blocks NO. One refinement in `event_zero/families.py`
(`script_line_ledger`): a bare call to a function defined in the same
file counts as structural, because the body's own lines are ledgered
individually; a call to an undefined name stays unaccounted. The gate
is scoped to identified scripts because a prose text file also
receives a display ledger (language None), and an unaccounted prose
line is not unaccounted behaviour; that scoping keeps
`test_valid_zip_still_enumerates_clean` (release notes in a zip)
passing without weakening the gate for code.

Regression tests: `test_defect4_unaccounted_line_blocks_no_for_any_script`,
`test_defect4_defined_function_call_is_accounted`.

Probe: before, the patcher script with one nonsense call line earned
`NO: ACCOUNTED`. After: `YES: UNACCOUNTED`, naming the line.

## 6. KMS baseline suppression (audit defect 6, P0)

Fix: `event_zero/verdict.py`. `kms_baseline` is content-only: strong
markers (`kmspico`, `kmsauto`, `autokms`, `gvlk`, `slmgr`,
`keymanagementservice`, "kms emulator", "kms server", "kms host",
"kms client") in the file's strings or full script source. The
filename never qualifies, and a bare "1688" substring never qualifies
(it fired on unrelated digit strings and filler). New helpers
`_ip_is_local` (real `ipaddress` range tests: loopback, private,
link-local, unspecified) and `external_contacts` (any URL, any
non-local IP, any bare domain except provably internal suffixes and
localhost) replace the prefix test that classified all of
172.0.0.0/8 as local. Both KMS suppression sites (the scope test and
the persistence-plus-C2 chain suppression) and the keygen-baseline
path now use the same helpers.

Regression tests: `test_defect6_kms_name_pair_same_verdict`,
`test_defect6_baseline_ignores_filename_and_bare_port_digits`,
`test_defect6_external_address_test`.

Probe: before, the pair agreed at PROVEN in this probe build (both
files were convicted by a ledger-flagged line), while the audit's
control pair proved the name dependence through the baseline path;
the defective mechanics (filename keying, "1688" keying, the 172/8
prefix test, bare domains treated as local) are pinned directly by
the unit regression tests. After: identical bytes under both names
give the identical verdict, the baseline ignores names and bare port
digits, and 172.217.14.206 tests as external.

## 7. classify_diff license-flag-flip fallback and vacuous region check (audit defect 7, P0)

Fix: `event_zero/verdict.py`. In `_crack_pattern`, a small
equal-length change is named `license-flag-flip` only with real
license context (LICENSE_WORDS) and `checksum-or-integrity-fix` only
with checksum or integrity context; otherwise it falls through and,
matching nothing, is unaccounted. `_region_capability_check` now
profiles the region's own bytes in addition to the enclosing spans,
decodes the instruction at the region start in both x86 modes
(`_region_instruction_profile`), fails the check when nothing at all
could be profiled (no strings, capabilities, indicators, or decodable
instruction), and flags a changed direct call target as an added
indicator. A conditional jump flipped to an unconditional jump to the
same target, the canonical crack, is not flagged, and text regions
skip the instruction comparison.

Regression tests: `test_defect7_settings_change_is_not_a_license_flag_flip`,
`test_defect7_region_capability_check_not_vacuous`. The existing
`test_genuine_branch_patch_still_expected_crack` still passes.

Probe: before, `classify_diff` returned
`[('expected-crack', 'license-flag-flip')]` for the LIMIT 1000 to
9999 settings change and the verdict was `NO: ACCOUNTED`. After:
`[('unaccounted', None)]` and `YES: UNACCOUNTED`.

## 8. Failed containers (audit defect 8, P1)

blocker recorded at enumeration stands, so the file is YES
UNACCOUNTED. Known-bad-hash PROVEN is untouched (hash identity does
not depend on content), and the file_yes branch can no longer
override the blocker because no yes-reasons are produced for the
file.

Regression test: `test_defect8_failed_container_never_proven`.

Probe: before, the stored zip with a flipped member CRC and a stealer
script inside earned `YES: MALWARE FOUND / PROVEN`. After:
`YES: UNACCOUNTED`, file verdict `YES: UNACCOUNTED`.

## 12. CRC32 and MD5 manifest matches are weak evidence (audit defect 11, P2)

Fix: `event_zero/verdict.py`. A manifest match on an 8-hex (CRC32,
the .sfv case) or 32-hex (MD5) value sets
`rec["reference"] = "manifest-match-weak"` with an explanatory note:
corroboration only, never an accounting, because both values can be
forged onto different bytes by construction. SHA-1 and SHA-256
matches still confer full `manifest-match`.

Regression test: `test_defect12_crc32_sfv_match_is_weak_only` (the
forged file is padded to the genuine file's CRC32 with a GF(2)
suffix solver, exactly the audit's construction).

Probe: before, the forged collision earned `NO: ACCOUNTED` on the
.sfv match. After: `YES: UNACCOUNTED`, reference recorded as
`manifest-match-weak`.

## 15. Silent analysis caps become explicit markers (audit defect 18, P2)

Fix: `event_zero/analyzer.py` assembles `report["truncations"]` for
every cap that cut material: the 200,000-byte code window (fallback
path), the 4,000-instruction disassembly cap, the 500-symbol cap
(`symbols_truncated`, newly recorded in `lief_parse`), entropy map
coverage past 16,384 bytes, the 500-instruction emulation budget,
and a script that could not be fully decoded. `event_zero/verdict.py`
turns each marker into a per-file unaccounted blocker, exempting
files accounted by byte identity (hash match or a strong manifest
hash, which do not depend on the truncated analysis) and container
entries. The entropy marker gates NO because the entropy regions
feed the logic-bomb opacity test and the sideload sidecar test. The
symbol list is consumed by no verdict path, so its marker is
record-only in effect for most files (it rides the same list; files
with over 500 symbols and no byte-identity accounting are blocked,
the fail-closed reading). Entry-stub trace gaps: a virtualized file
is blocked outright unless every differing region is diff-classified,
and in that patch-area case the verdict now records the gap count in
the file's why text, noting the accounting rests on the diff ledger,
not the trace.

Regression tests: `test_defect15_truncation_markers_recorded_and_block`,
`test_defect15_small_files_unaffected`.

Probe: before, a 19,380-byte benign script earned `NO: ACCOUNTED`
and `report["truncations"]` was None for every input. After: the
script is `YES: UNACCOUNTED` with the truncation named, and the
markers are recorded (entropy coverage for the big script, the
emulation budget for the NOP PE).
